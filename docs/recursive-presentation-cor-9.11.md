# Recursive presentations and Corollary 9.11

This note records why `RecursivePresentation` includes a computable
sup-closure operation on formula codes, and why that field is part of the
paper's notion of a *countable, recursive language* rather than a
strengthening of Corollary 9.11.

The corresponding Lean docstring is on `RecursivePresentation` in
`ContinuousFOL/Completeness/RecursivePresentation.lean`.

## 1. What the paper assumes

§1 of Ben Yaacov–Pedersen, *A proof of completeness for continuous first-order
logic* (JSL 75, 2010):

> When is the set of all consequences of a theory (in a countable, recursive
> language) recursive? […] As in classical first-order logic, it follows from
> the completeness theorem of continuous first-order logic that if a complete
> theory admits a recursive (or even recursively enumerable) axiomatization
> then it is decidable.

Definition 9.10:

> Let \(T\) be a theory. (i) If \(T\) is complete, we say \(T\) is
> *decidable* if for every sentence \(\varphi\), the value
> \(\varphi^{\circ}_T\) is a recursive real and uniformly computable from
> \(\varphi\). (ii) If \(T\) is incomplete, we say \(T\) is *decidable* if
> for every sentence \(\varphi\) the real number \(\varphi^{\circ}_T\) is
> uniformly recursive from \(\varphi\).

Corollary 9.11:

> Every complete theory with a recursive or recursively enumerable
> axiomatization is decidable.

The corollary is stated without a separate proof; it is the classical
consequence of completeness, transferred to continuous first-order logic, in
a countable recursive language.

## 2. Why the earlier Lean fields did not formalize the corollary

An earlier version of `RecursivePresentation` asked only for:

- an injective numbering of formulae, with a decidable set of codes;
- a computable operation \((\varphi,\psi)\mapsto\varphi\dot{-}\psi\) on codes;
- computable codes for the dyadic constants \(k/2^n\);
- an r.e. set of codes of the logical axioms (all generalizations of
  (A1)–(A14)).

Those fields make the *proof system* of §7 effective: from an r.e. set of
premises, the set of codes of theorems is r.e. (`provableMetricQ_codes_re`).
They do not, however, give computable access to the rest of the syntax of
\(\mathrm{For}(\mathcal{L})\). In particular they do not let us compute, from
the code of \(\varphi\), the free variables of \(\varphi\), or the code of
its *sup-closure* (the sentence obtained by binding those free variables, in
a fixed order, by a prefix of \(\sup\)).

Definition 9.10 and Corollary 9.11 ask for a *uniform* algorithm: a single
computable function which, given the code of a sentence and a precision
\(n\), returns a dyadic approximation of \(\varphi^{\circ}_T\) to within
\(2^{-n}\). In Lean this is a computable map \(\mathbb{N}\to\mathbb{N}\to
\mathbb{Z}\), and every such map must halt on *every* input, including codes
of open formulae and numbers that are not codes at all.

Non-codes can be rejected, because the set of codes is decidable. Open
formulae cannot be ignored in the same way. Over a complete theory,
two-sided dyadic cuts close in on the value of a *sentence*, because every
model of \(T\) realises the same value. An open formula need not: already
for a metric, \(d(x,c)\) depends on the assignment, so there can be a
positive gap between the infimum and the supremum of the values of
\(\varphi\) in models of \(T\). A search for tight cuts of \(\varphi\)
itself therefore need not halt on an open-formula code.

Two obvious workarounds fail without a further syntax operation:

- Test whether the input names a sentence, and if not, return a dummy. That
  test is “the set of free variables is empty,” which is not computable from
  the earlier fields.
- Replace \(\varphi\) by its sup-closure sentence, and run the cut search on
  that sentence. Forming the closure is exactly the operation
  `supClosureCode`.

So, with only the earlier fields, Corollary 9.11 as formalized was not
provable. The Lean hypothesis was strictly weaker than the paper’s intended
“countable, recursive language.”

### A pathological numbering

The earlier operations present only a fragment of the formula algebra: the
universe of codes, \(\dot{-}\), and the dyadic constants. A numbering may
compute those and still fail to compute free variables or sup-closure.

Concretely, start from a standard Gödel numbering \(e\), and use an
undecidable set (for example the halting set) to relocate the codes of
formulae that lie *outside* the subalgebra generated by the dyadic constants
under \(\dot{-}\). That subalgebra does not include quantified formulae, nor
in general atomic formulae with free variables. One can adjust the table for
\(\dot{-}\) so that it remains a computable function of the relocated codes,
keep the set of all formula codes decidable (for instance recursive of
finite complement, or all of \(\mathbb{N}\)), and keep the set of logical
axiom codes r.e.: the axioms are r.e. in \(e\), and relocating an r.e. set
along an injective map with r.e. graph can be arranged to stay r.e. Under
such a numbering there is no algorithm that, given
\(\ulcorner\varphi\urcorner\), returns \(\ulcorner\sup^*\varphi\urcorner\)
or the list of free variables. No uniform procedure built from the old
fields can recognise sentences or form their closures, and the two-sided
search is then not a total computable function.

## 3. Why `supClosureCode` is exactly the standard meaning

A standard Gödel numbering of a recursive language makes *every* syntactic
operation computable: the constructors and destructors for every clause of
the inductive definition of formulae, including \(\sup_x\), and hence the
finite list of free variables and the sup-closure. Adding a single
computable map `supClosureCode`, specified to send the code of \(\varphi\)
to the code of its sup-closure, is a minimal fragment of that standard
package — exactly the operation used to make the algorithm of Corollary 9.11
total, and nothing stronger.

This is not a new mathematical hypothesis. It records, in the Lean model of
the paper’s “countable, recursive language,” a syntactic operation that any
such presentation already provides. The statement of Corollary 9.11
(`complete_re_theory_decidable`) is otherwise unchanged: a complete theory
with a recursive or r.e. axiomatization is decidable, in the sense of
Definition 9.10, relative to that presentation.
